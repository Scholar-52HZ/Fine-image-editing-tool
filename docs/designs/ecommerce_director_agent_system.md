# 导演级电商视觉工厂：轻量工作流设计方案

> 设计版本：v3.1-design，2026-10-17。
> 状态：依据用户本轮指示修订设计，尚未实现。
> 核心定位：一键创作、内部工作流、按需局部重做、轻量化。
> 架构依据：ADR-012/014；本轮增补 ADR-016。未来桌面交付继续遵循 ADR-011。
> 复审证据：[2026-10-17 设计复审](ecommerce_director_design_review_2026-10-17.md)。历史 v2/v3 工作流为背景材料；本文件为 TASK-007 当前实施依据。

## 1. 产品目标与交互

保留“真实商品资产 × 自由场景 × 模板镜头、情绪与叙事”的原始设计。用户上传商品图片、填写商品资料、描述希望场景并选择风格，即可一键生成成套作品。镜头数量和模块组合由需求、模板与可用素材共同决定。

默认展示作品预览和简洁进度；按需展开分镜、背景、文案与构图，允许锁定满意内容并局部重做。正常任务自动完成，不要求逐节点配置或逐阶段确认。只有素材不足、商品事实缺失或预算需要扩大等情况才提示用户处理；可跳过的模块应提供明确选择。

基础抠图保留“上传—调整—导出”，批量抠图使用任务队列。整个工具复用任务状态与资产约定，简单操作直接调用现有管线，不强行经过 AI 分镜。首版交付预设流程和参数调整，不建设自由节点编辑器。

轻量化不能以删除场景自由度、商品保真、风格统一或 A/B 接入能力为代价。实现成本通过按需执行、依赖隔离与资产复用控制。

## 2. 系统分层与执行链路

~~~mermaid
flowchart TD
    U["商品图片 / 商品事实 / 自由场景 / 风格模板"] --> UI["一键创作与作品编辑"]
    UI --> W["进程内工作流调度 / 状态 / 缓存 / 预算"]
    W --> P["素材检查与抠图"]
    P --> A["感知 / 导演 / 文案规划"]
    A --> V["结构与事实校验"]
    V --> G["独立背景生成适配器"]
    G --> C["真实主体本地合成"]
    C --> R["HTML / SVG 模板排版"]
    R --> Q["质量检查 / 图片与 ZIP 导出"]
    W --> L["统一语言网关：本地 A / 云端 B"]
    A --> L
    W --> S["任务 JSON 清单与文件资产"]
~~~

工作流负责依赖、预算、状态和恢复；AI 负责需要语义理解的创作；本地图像引擎负责可验证的裁剪、合成与导出。业务逻辑置于 core，Gradio 及未来桌面前端只调服务接口，避免未来维护两套流程。

保留四个专业角色，但角色是职责划分，不对应四个常驻进程或四套模型。商品感知按需调用视觉模型；导演与文案可共享一次结构化规划；合成排版由确定性代码执行。首版不引入开放式 Agent 互相讨论或无限自我修正。

## 3. 轻量化约束与验收口径

### 3.1 依赖和分发

- 工作流首版使用 Python 函数、轻量数据对象、标准库任务控制和 JSON 清单；不引入重型 Agent/工作流框架、Redis、独立消息队列、数据库、向量库或微服务集群。
- 主程序保持轻量 API 客户端与本地合成能力。大语言模型、扩散模型、Ollama/ComfyUI 等伴侣运行时独立安装，主程序不自动捆绑、拉取或启动它们。
- 优先复用现有依赖；新增直接依赖必须说明用途、可替代性及实际体积。HTTP 通信收敛到一种实现，避免为每家服务商安装一套 SDK。
- HTML/SVG 排版按能力加载；渲染运行时与字体包单独核算。优先评估复用可用运行时，只有真实验证兼容性后才能决定交付方式。首版不默认捆绑第二套浏览器运行时。
- 新版排版逐步接入，继续复用 Pillow/OpenCV 的裁剪、遮罩、合成与编码；旧版电商路径保留至新版验收。
- 当前源码环境不等于安装包：Python、Gradio、ONNX、浏览器、字体和模型都要计入所属分发层，不再将“整个安装包几十 MB”当作已经达成的承诺。

### 3.2 初始工程预算

以下为待验证的设计预算，必须在原型报告中记录实测结果；不是现有效能数据。

| 项目 | 首版约束或目标 | 测量边界 |
| --- | --- | --- |
| 工作流新增依赖 | 编排层新增第三方依赖为 0 | 不包含既有图像/UI 依赖；适配与渲染新增依赖单独披露 |
| 编排增量内存 | 相对相同输入的直接管线，峰值 RSS 增量目标 ≤64 MiB | 排除模型/渲染器本体但分别记录；包含编排缓存，重复样本比较 |
| 大图任务并发 | 本地图像重任务默认 1，文本请求最多 2 | 共享设备预算，外部本地生图也进入重任务调度 |
| 预览尺寸 | 长边默认 ≤1280 像素 | 最终导出从原始资产重渲染，不放大预览图冒充高清 |
| AI 自动调用 | 标准任务规划目标 1~2 次，结构修复最多 1 次 | 生图按实际镜头单独计数、计费；质量检查不触发自动无限重生 |
| 自动网络重试 | 单请求最多 1 次重试 | 仅可安全重试的失败；付费生图按任务查询/幂等能力处理 |
| 运行任务缓存 | 可再生缓存默认配额 1 GiB | 原图、用户锁定资产及最终输出不自动删除；配额不足时停止新增缓存并提示 |
| 本地队列 | 单执行器，默认最多 10 个待处理任务 | 超额明确反馈；原型阶段用压力样本验证 |
| 分发体积 | 每次交付报告分层实测，正式上限在渲染原型后确定 | 主程序、Python/库、字体/渲染、模型、外部伴侣分别列明 |

轻量验收同时记录冷启动、空闲驻留、峰值内存/显存、缓存占用和各阶段耗时。超过预算先检查重复加载、图片副本和无效调用，不静默降低导出质量。

## 4. AI 与图像服务边界

### 4.1 双轨语言网关

保留方案 B（默认配置入口，标准兼容 API）与方案 A（外部本地 Ollama）。默认配置入口不代表程序启动即联网；仅用户执行相关功能时发出请求。服务商预设为可更新配置，实际能力按模型测试结果判断。

统一请求包含文本/图片内容块、目标 schema、超时与请求 ID；响应包含结构化数据、模型、结束原因、耗时、可用用量与标准错误。诊断分别报告对话、视觉、结构化能力；只有问候请求成功不能宣称商品感知可用。

能力记录为 text、vision、structured_output、image_generation、masked_edit；声明与实测状态分开。视觉感知可使用低分辨率副本，局部工艺按需发送 ROI，原始资产本地保存。纯文本模型不承担看图任务。

### 4.2 独立图像服务协议

语言网关规划场景，图像适配器生成背景；二者配置和诊断独立。首版协议支持提交、状态查询、取消（提供方支持时）及资产取回。输入包含提示词、画布、主体预留区、文字安全区、支撑平面、光向与可选 seed；结果记录任务 ID、实际尺寸、参数及图像资产。

首个实际适配器在阶段 1 收口时选定；原型必须接通至少一个真实图像服务，不能只用模拟响应宣称自由场景完成。后续按需求增加提供方，首版不建设通用插件市场。

默认生成背景后回贴真实主体，不通过生成模型重绘商品。掩膜编辑作为扩展能力。无生图服务时可使用用户背景/本地背景完成合成，并明确本次属于背景合成模式。

### 4.3 本地、云端与凭证

基础抠图可以独立离线运行；完整离线创作要求外部本地模型与生图服务已安装就绪。本地模式不得自动转云端。伴侣不就绪时保留基础能力，提示需要配置的具体能力。

凭证默认使用环境变量或会话内存；JSON 只持久化非敏感配置。凭证不得进入日志、任务清单或导出 ZIP。共享 WebUI 的会话配置相互隔离，任务开始后使用固定配置快照。

未来桌面主程序与外部伴侣服务的“零端口”适用边界仍需单独澄清；本轮不修改 ADR-011 的既有承诺。

## 5. 最小数据契约与真实资产保护

首版采用版本化数据对象，避免构建复杂通用 DSL。每阶段输出均做结构校验和业务校验。

| 对象 | 必备内容 |
| --- | --- |
| ProductAsset | ID、哈希、原始尺寸、视角/状态、原图与遮罩引用、可用 ROI |
| ProductFacts | 属性值、单位、来源、用户确认状态；未知值为空 |
| StyleSpec | 色板、光向、字体层级、留白、情绪与版本 |
| TemplateManifest | 所需素材、适用品类、模块顺序、主体/文字安全区、字数行数限制 |
| ShotPlan | 镜头 ID、真实 asset_id、裁剪框、商品目标区域、背景描述、模板与事实引用 |
| JobManifest | UUID、schema/流程版本、输入哈希、脱敏配置快照、节点状态、预算、资产清单 |
| RenderArtifact | 输出尺寸、文件哈希、输入引用、处理记录、检查结果 |

坐标声明归一化或像素坐标系，执行前校验边界、主体交集及最小有效像素。分镜必须匹配真实视角和状态；单张正面图不得补造侧面、折叠态、手持态或不存在的细节。缺图时改用现有镜头、跳过模块或提示补图。

保真是保护结构、包装文字与 Logo，并保留可追溯的变换；抠图、缩放、羽化或去色溢会影响像素，不能笼统保证合成图与原图逐像素相等。保存原始资产，记录处理范围，允许关闭颜色修改。尺寸箭头与参数只取自确认资料；不得从无标定单图推算真实毫米数据。功效、认证、口碑和促销同样不得凭空补写。

## 6. 工作流状态、恢复与局部重做

### 6.1 执行和持久化

固定依赖图为：素材检查/抠图 → 事实与风格 → 分镜与文案 → 计划校验 → 背景 → 合成 → 排版 → 检查 → 导出。可用模块由计划决定；不需要背景的参数图跳过生图。正常任务校验通过后自动继续，计划编辑是可选操作。

节点状态包括 pending、running、succeeded、failed、blocked、cancelled、stale。工作流 JSON 清单记录节点输入指纹和产物引用，图像按文件存储，不把 base64 大图反复写入清单。使用临时清单后原子替换，完成产物落盘后才标成功。

首版同一任务只有一个执行者；进程重启后把遗留 running 状态标为待核验，先核查产物或外部任务状态，再由用户恢复。取消停止后续调度；不宣称已经撤回不可取消的外部调用或费用。

运行任务保存到 outputs/director_jobs/<job_id>/，遵循 outputs 的忽略规则；开发草稿继续放 .ai/scratch，预览实验放 .ai/artifacts。流程清单和用户资产保留至用户删除，缓存配额只作用于可再生产物。

### 6.2 依赖失效规则

| 用户修改 | 保留与重做范围 |
| --- | --- |
| 标题或卖点文字 | 保留抠图、背景、合成；重新排版、检查与打包 |
| 背景场景 | 保留事实、可复用抠图与文案；重生受影响背景及下游 |
| 同视角商品位置/缩放 | 构图仍满足场景约束则复用背景，否则连背景一起失效 |
| 替换原图或修改抠图 | 重检素材，失效所有依赖旧资产的模块 |
| 字体或纯排版模板参数 | 只重排版；若改变主体/文字安全区则检查背景与构图 |
| 整套风格或镜头 | 重规划受影响模块，核验背景、合成与文案一致性 |

锁定对象携带其输入指纹。用户修改与锁定内容的前提冲突时，提示解锁、保留旧版本或取消修改，不能静默复用不兼容资产。重做只刷新依赖下游；产物以新版本保存，成功后再切换当前引用。

缓存键包括输入哈希、相关参数、模型、模板、提示词和流程版本；只复用匹配且校验存在的资产。文本和任务配置修改不应误复用旧计划。相同 seed 不代表生成可复现，背景文件本身需要保留。云任务超时先查询；不支持查询或幂等时标为结果未知并提示，不自动重复扣费。

## 7. 模板排版与成套质量

整套作品共享 StyleSpec，模板规定镜头语法、色板、文字层级与安全区。背景须满足支撑面、地平线、光向和主体留白；ROI、事实引用、标题长度、字体加载、越界和尺寸由程序检查。

新版排版以受控 HTML/CSS/SVG 模板实现。渲染器只接收转义后的数据和允许的本地资产，不执行 AI 返回的任意页面或脚本。字体/图标本地提供，严格本地模式阻断外部资源请求。

先完成一个最小模板的中文、透明度、阴影与离线渲染验证，再确定唯一主渲染路线；完整模板优先落地美妆轻奢和户外装备。镜头和模块数量可变，CAD 模块仅在真实尺寸就绪时提供。

输出以具体宽高和色彩模式验收，4K 明确长边规格并提示低分辨率放大；DPI 元数据不代表新增细节。长图逐模块渲染与拼接，及时释放中间图像，设最大画布像素数并在分配前检查。复用任务级渲染实例，任务结束释放，不常驻后台浏览器。

人工视觉验收关注商品辨识度、透视接触、光向、文字节奏和套图一致性；自动检查通过不能替代视觉验收。参考图需以项目可访问素材保存并注明来源范围。

## 8. 四阶段交付与关口

| 阶段 | 交付范围 | 通过标准 |
| --- | --- | --- |
| 1：协议与网关 | 版本化对象、能力诊断、A/B 语言适配、图像协议、配置中心、执行器骨架 | 模拟验证成功/失败/超时/取消/结构错误/脱敏；选定一个可实测图像服务；编排新增第三方依赖为 0 |
| 2：单主图闭环 | 一张真实商品图、一套风格、可执行分镜、背景服务、本地合成、最小渲染模板 | 一键得到真实成图；缺素材可降级；无需逐节点确认；记录调用、耗时与内存 |
| 3：模板与质量 | 美妆/户外模板、事实来源、局部重做、锁定冲突、资源预算验证 | 改文案不重生背景；中文/字体/越界检查通过；固定样例经用户视觉评审 |
| 4：成套交付 | 1~6 图映射、多模块、进度取消、故障恢复、缓存清理、ZIP | 共享风格；失败后可恢复；锁定资产不被清理；队列与内存压力验证通过 |

不在本任务同时重构现代前端或完成桌面打包。阶段 1 只搭骨架，不为未来自由节点编排预建插件、流程市场或分布式系统。

## 9. 文件边界与下一步

规划目录（尚未实现）：core/workflow 下放 schemas、runner、store；core/agents 保留语言适配与专业角色；core/providers 放图像协议与选定适配器；core/pipeline 复用图像能力并增加模板/渲染；ui/web/service.py 调度，ui/web/app.py 展示。新增文件按阶段需要创建。

下一步从阶段 1 开始：先实现版本化数据契约与最小执行器，再接语言/图像适配和配置面板。真实服务商、渲染运行时及预算达成情况在原型后记录，不能将设计目标标记为已交付。
